## 온라인 (2시수)

### 강의: 텐서 연산과 자동미분, 사전학습 모델 로딩

□ 텐서 - 숫자를 담는 상자

- 텐서(tensor)는 겁낼 것 없이 **숫자를 담는 상자**다. 상자의 모양에 따라 이름만 달라진다
- 스칼라: 숫자 하나 (예: 오늘 기온 27)
- 벡터: 숫자를 일렬로 놓은 것 (예: 일주일치 기온 7개)
- 행렬: 숫자를 바둑판처럼 놓은 것 (예: 반 학생 30명의 국어·영어·수학 점수, 30줄 x 3칸)
- 그 이상: 행렬을 여러 장 쌓은 것 (예: 우리 학년 5개 반 전부의 점수)
- NLP에서 텐서가 하는 일: 글자를 숫자로 바꿔 담고(임베딩), 행렬 곱셈으로 표현을 섞고, 마지막에 확률로 낸다. 모델의 가중치(모델이 기억하는 값)도 전부 텐서다. "모델이 크다"는 말은 곧 "텐서가 크다"는 말이다
- GPU가 잘하는 일이 바로 이 텐서 연산을 **수천 개씩 동시에** 하는 것이다. 같은 계산을 엄청나게 많이, 동시에 - 이것이 AI에 GPU가 필요한 이유다

□ 자동미분 - 어디서 틀렸는지 거꾸로 따라가기

- 모델을 가르치려면 "얼마나, 어느 쪽으로 틀렸는지"를 알아야 한다. 그 답이 **그래디언트(기울기)** 다
- 비유: 시험에서 감점됐을 때 "어느 문제의 어느 풀이 단계에서 점수가 깎였나"를 거꾸로 추적하는 것과 같다. 총점(손실)만 봐서는 고칠 곳을 모른다. 단계별 감점(각 가중치의 그래디언트)을 알아야 고친다
- 원리는 하나다. `requires_grad=True`로 표시한 텐서에 연산을 걸면, 프레임워크가 **연산 기록(계산 그래프)** 을 메모해 둔다. `loss.backward()`를 부륩면 그 메모를 거슬러 올라가며 각 텐서의 감점표(그래디언트)가 채워진다
- 실습 노트북 1-1의 실측값으로 확인한다. `loss = (w*x + b - 10)^2`이고 `w=2, x=3, b=1`일 때:

| 항목 | 값 | 뜻 |
|---|---|---|
| loss | 9.0000 | (2 x 3 + 1 - 10)^2 = (-3)^2 |
| d(loss)/dw | -18.0000 | w를 조금 키우면 loss가 그 18배만큼 줄어드는 방향 |
| d(loss)/dx | -12.0000 | x에 대한 기울기 |
| d(loss)/db | -6.0000 | b에 대한 기울기 |

- 손으로도 확인해 본다. `w*x+b = 7`이고 `loss = (7-10)^2 = 9`. 미분의 연쇄법칙(겉미분 x 속미분)으로 `d(loss)/dw = 2*(7-10)*x = -18`. 코드 출력과 정확히 일치한다. **자동미분은 마법이 아니라 연쇄법칙을 기계가 대신 적용해 주는 것**이다

□ 학습 루프 - 네 단계의 반복

- 모델을 가르치는 일은 다음 네 단계를 **수백, 수천 번 반복**하는 것이다
- 순전파: 입력을 넣어 예측을 계산한다 (문제를 푼다)
- 손실: 예측과 정답의 차이를 숫자 하나로 만든다 (채점한다)
- 역전파: `loss.backward()`로 각 가중치의 그래디언트를 구한다 (감점 원인을 추적한다)
- 갱신: `w -= lr * w.grad`로 그래디언트 반대 방향으로 한 걸음 이동한다 (틀린 쪽의 반대로 고친다). `lr`(학습률)은 한 걸음의 크기다

<img src={trainingLoop.src} alt="순전파, 손실, 역전파, 갱신의 네 단계가 원형으로 반복되는 학습 루프 다이어그램" style="max-width: 100%; border-radius: 8px; margin: 1rem 0;" />

- 실습 노트북 1-2의 실측값. 정답이 `y = 3x + 1`인 데이터를 맞추는 선형 모델이다. 처음에는 w=0.5, b=0으로 엉터리지만, 반복할수록 정답에 다가간다:

| step | loss |
|---|---|
| 0 | 60.375000 |
| 40 | 0.002392 |
| 80 | 0.001861 |
| 120 | 0.001464 |
| 160 | 0.001152 |

<img src={lossDescent.src} alt="학습 step이 진행될수록 손실이 60.375에서 0.001152로 떨어지는 실측 그래프" style="max-width: 100%; border-radius: 8px; margin: 1rem 0;" />

- 200 step 후 `w = 3.025, b = 0.926`. 정답(w=3, b=1)에 거의 도달했다. **손실이 낮아지는 것 = 모델이 데이터에 맞춰지고 있다는 증거**다. 이 그림 한 장이 "학습된다"는 말의 전부다
- 손실 함수(채점 기준)를 바꾸면 같은 데이터에서도 감소 곡선이 달라진다. 평균제곱오차(MSE)는 큰 오차를 세게 혼내고(제곱이라), 평균절대오차(MAE)는 오차 크기만큼만 혼낸다. 이것이 이번 주 노트북의 TODO 한 지점이다

□ 사전학습 모델 로딩 - 길들여진 용병 데려오기

- 우리는 가중치를 처음부터 만들지 않는다. 이미 엄청난 분량의 글을 읽고 학습된 모델을 **그대로 가져와** 그 위에서 작업한다. 새 직원을 뽑아 1부터 가르치는 대신, 경력직을 데려오는 것과 같다
- 로딩은 두 조각이다. **토크나이저**(글자를 잘라 숫자로 바꾸는 번역기)와 **모델**(그 숫자를 받아 계산하는 본체)
- 실습에서 쓰는 한국어 모델(KoELECTRA base)의 전체 파라미터 수는 **112,922,882개(약 1.1억)** 다. 이 숫자를 기억해 둔다. 3주차에서 LoRA가 학습 파라미터를 얼마나 줄이는지 이 수가 기준선이 된다
- 분류 과제용으로 불러오면 분류 헤드(마지막 판정 부품) 가중치가 체크포인트에 없어서 **새로 초기화**된다는 경고가 뜬다. 고장이 아니라 "이 부품은 직접 데이터로 새로 길들여야 한다"는 안내다

### 학습활동

- 튜토리얼 코드(실습 노트북)를 한국어 데이터로 바꿔 실행하고, 막힌 지점을 튜터에게 질의한다
- 질의할 때는 오류 메시지의 **마지막 줄**을 함께 제시한다. 긴 오류문의 첫 줄이 아니라 마지막 줄에 진짜 원인이 적혀 있다

## 대면 (1시수)

### 어텐션 커널 최적화(FlashAttention 계열)의 아이디어 개관

□ 왜 커널(계산 부품) 이야기를 하는가

- 1주차에서 어텐션은 제곱으로 늘어난다고 배웠다. 그런데 실제 GPU에서 돌려 보면, 수식상의 계산량보다 **데이터를 이리저리 옮기는 일**이 더 큰 병목인 경우가 많다
- 비유: 요리사가 칼질(연산)을 아무리 빨리 해도, 재료를 먼 창고(느리고 큰 메모리, HBM)에서 조리대(빠르고 작은 메모리, SRAM)로 오가는 시간이 더 걸리면 전체 요리는 늦어진다
- FlashAttention(arXiv:2205.14135, NeurIPS 2022)은 바로 이 왕복을 줄인다. 어텐션의 **수식은 그대로 두고**(근사가 아니라 정확한 어텐션) 계산 순서를 GPU 메모리 구조에 맞게 재배열한다

□ 핵심 아이디어 두 가지

- 타일링(tiling): 재료를 한꺼번에 다 꺼내지 않고 **한 번에 쓸 만큼만** 조리대에 올린다. 어텐션도 Q, K, V를 작은 조각으로 나눠 칩 안의 빠른 메모리에서 처리하니 창고 왕복이 줄어든다
- 재계산(recomputation): 요리 중간 재료를 전부 창고에 보관해 두지 않고, 필요할 때 **다시 만든다**. 어텐션도 거대한 중간 행렬(n x n)을 저장하지 않고 역전파 때 재계산해서, 메모리가 시퀀스 길이에 비례해서만 늘어난다
- 후속작 FlashAttention-2(arXiv:2307.08691)는 GPU 안에서의 일 분배를 다듬어 같은 하드웨어에서 처리량을 더 끌어올렸다

□ 우리 수업과의 연결

- "같은 모델인데 왜 이 환경에서는 느린가"의 답 절반은 수식이 아니라 **커널과 메모리**에 있다
- 우리가 커널을 직접 짤 일은 없다. **라이브러리가 이미 만들어 둔 최적화를 알고 선택하는 것**이 실무 역량이다. 도내 소규모 조직처럼 장비가 부족한 조건일수록 이 선택이 비용을 가른다

### 온라인에서 막힌 지점 공동 해결

- 사전에 수집한 질문을 화면 공유로 함께 재현하고 고친다
- 흔한 지점: 라이브러리 버전 차이, 파일 경로, 텐서 모양(shape) 불일치. 오류 메시지 마지막 줄 읽는 습관을 반복한다

□ 토크나이저가 글자를 자르는 모습 (실측)

- 토크나이저는 자주 본 글자 덩어리는 통째로, 낯선 덩어리는 잘게 쪼갠다. 사전학습 토크나이저는 표준어 글을 많이 읽고 만들어졌으므로, 제주 방언 표기는 낯설어서 **더 잘게 쪼개지는 경향**이 있다

□ 노트북 샘플 실측값 (KoELECTRA 토크나이저 기준)

| 방언 | 토큰 수 | 표준어 | 토큰 수 | 차이 |
|---|---|---|---|---|
| 혼저 옵서예. | 6 | 어서 오세요. | 4 | +2 |
| 마씀 | 2 | 말씀 | 1 | +1 |
| 고맙수다 | 3 | 고맙습니다 | 3 | 0 |

- 토큰 수 증가는 곧 입력 길이·연산·비용의 증가다. 1주차의 제곱 법칙과 만나면 차이는 더 커진다
- 같은 뜻인데 표기만 다르다고 비용이 달라진다면, 방언 화자를 대상으로 한 서비스의 단가는 어떻게 산정해야 하는가. 이 질문이 실무 활동의 출발점이다

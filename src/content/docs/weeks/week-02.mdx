## 이번 주차

구현 기반 - 학습 루프와 텐서 연산

□ 이 주차가 놓이는 자리

- 1주차에서 어텐션의 비용 구조와 상태공간모델의 개념을 봤다. 2주차부터는 **직접 돌리는 단계**로 들어간다
- 이 주차에 만드는 학습 루프는 3주차 PEFT, 이후 프롬프트·RAG·정렬 실습까지 **전부 이 코드를 재사용**한다. 여기서 끝까지 돌려 보지 않으면 이후 주차가 성립하지 않는다
- 목표는 하나다. **전원이 학습 루프를 끝까지 돌려 손실이 낮아지는 것을 확인**하는 것

## 온라인 (2시수)

### 강의: 텐서 연산과 자동미분, 사전학습 모델 로딩

□ 텐서 연산

- 텐서는 숫자를 담는 다차원 배열이다. 스칼라(0차원), 벡터(1차원), 행렬(2차원), 그 이상을 한 이름으로 부른다
- NLP에서 텐서가 하는 일: 토큰을 숫자(임베딩)로 바꾸고, 행렬 곱셈으로 표현을 섞고, 확률로 낸다. 모델의 가중치도 전부 텐서다
- GPU가 잘하는 일이 바로 이 텐서 연산의 대량 병렬 처리다. "모델이 크다"는 말은 곧 "텐서가 크다"는 말이다

□ 자동미분(autograd)의 동작 순서

- `requires_grad=True`로 표시한 텐서에 연산을 걸면, 프레임워크가 **연산 기록(계산 그래프)** 을 남긴다
- `loss.backward()`를 부르면 그래프를 거슬러 올라가며 각 텐서의 그래디언트(기울기)가 채워진다
- 실습 노트북 1-1의 실측값. `loss = (w*x + b - 10)^2`, `w=2, x=3, b=1`일 때:

| 항목 | 값 |
|---|---|
| loss | 9.0000 |
| d(loss)/dw | -18.0000 |
| d(loss)/dx | -12.0000 |
| d(loss)/db | -6.0000 |

- 손으로 확인해 본다. `w*x+b = 7`이고 `loss = (7-10)^2 = 9`. 미분 연쇄법칙으로 `d(loss)/dw = 2*(7-10)*x = -18`. 코드 출력과 일치한다. **자동미분은 마법이 아니라 연쇄법칙의 기계적 적용**이다

□ 학습 루프의 네 단계

- 순전파: 입력을 넣어 예측을 계산한다
- 손실: 예측과 정답의 차이를 숫자 하나로 만든다
- 역전파: `loss.backward()`로 각 가중치의 그래디언트를 구한다
- 갱신: `w -= lr * w.grad`로 그래디언트 반대 방향으로 한 걸음 이동한다
- 실습 노트북 1-2의 실측값. `y = 3x + 1`을 맞추는 선형 모델, 학습률 0.01:

| step | loss |
|---|---|
| 0 | 60.375000 |
| 40 | 0.002392 |
| 80 | 0.001861 |
| 120 | 0.001464 |
| 160 | 0.001152 |

- 200 step 후 `w = 3.025, b = 0.926`. 정답(w=3, b=1)에 수렴한다. **손실이 낮아지는 것 = 모델이 데이터에 맞춰지는 것**이다
- 손실 함수를 바꾸면(평균제곱오차 → 평균절대오차) 같은 데이터에서도 감소 곡선이 달라진다. 이것이 이번 주 노트북의 TODO 한 지점이다

□ 사전학습 모델 로딩

- 우리는 가중치를 처음부터 만들지 않는다. 이미 대규모 말뭉치로 학습된 모델을 **그대로 가져와** 그 위에서 작업한다
- 로딩은 두 조각이다. **토크나이저**(글자를 토큰 숫자로)와 **모델**(토큰 숫자를 받아 계산)
- 실습에서 쓰는 한국어 모델(KoELECTRA base)의 전체 파라미터 수는 **112,922,882개(약 1.1억)** 다. 이 숫자를 기억해 둔다. 3주차에서 LoRA가 학습 파라미터를 얼마나 줄이는지 이 수가 기준선이 된다
- 분류 과제용으로 불러오면 분류 헤드(classifier) 가중치는 체크포인트에 없어서 **새로 초기화**된다는 경고가 뜬다. 오류가 아니라 "이 부분은 직접 데이터로 학습해야 한다"는 뜻이다

### 학습활동

- 튜토리얼 코드(실습 노트북)를 한국어 데이터로 바꿔 실행하고, 막힌 지점을 튜터에게 질의한다
- 질의할 때는 오류 메시지의 **마지막 줄**을 함께 제시한다. 첫 줄이 아니라 마지막 줄에 원인이 있다

## 대면 (1시수)

### 어텐션 커널 최적화(FlashAttention 계열)의 아이디어 개관

□ 왜 커널 이야기를 하는가

- 1주차에 어텐션의 O(n^2) 비용을 봤다. 그런데 실제 GPU에서 어텐션을 돌리면 이론상의 연산량보다 **메모리 왕복**이 병목이 되는 경우가 많다
- FlashAttention(arXiv:2205.14135, NeurIPS 2022)은 이 지점을 공략한다. 어텐션의 **수식을 바꾸지 않고**(정확한 어텐션, 근사 아님) 계산 순서를 GPU 메모리 구조에 맞게 재배열한다

□ 핵심 아이디어 두 가지

- 타일링(tiling): Q, K, V를 한꺼번에 올리지 않고 작은 조각으로 나눠, GPU 칩 안의 빠른 메모리(SRAM)에서 어텐션을 계산한다. 크고 느린 메모리(HBM)와의 왕복 횟수가 줄어든다
- 재계산(recomputation): 역전파 때 필요한 중간 결과(n x n 어텐션 행렬)를 저장해 두지 않고, 순전파 결과만 저장했다가 역전파 시 다시 계산한다. 메모리 사용이 시퀀스 길이에 대해 선형으로 줄어든다
- 후속작 FlashAttention-2(arXiv:2307.08691)는 GPU 안에서의 작업 분배를 다듬어 같은 하드웨어에서 처리량을 추가로 끌어올렸다

□ 우리 수업과의 연결

- "같은 모델인데 왜 이 환경에서는 느린가"에 대한 답의 절반은 수식이 아니라 **커널과 메모리**에 있다
- 도내 소규모 조직처럼 GPU가 부족한 조건에서 시퀀스 길이를 어느 선까지 감당할지 판단하려면, 이 비용 구조를 알아야 한다. 직접 커널을 짜지는 않는다. **라이브러리가 이미 제공하는 최적화를 선택할 줄 아는 것**이 실무 역량이다

### 온라인에서 막힌 지점 공동 해결

- 사전에 수집한 질문을 화면 공유로 함께 재현하고 고친다
- 흔한 지점: 라이브러리 버전 차이, 경로, 텐서 모양(shape) 불일치. 오류 메시지 마지막 줄을 읽는 습관을 반복한다

## 학습활동

**[이론]** 자동미분과 역전파가 학습 루프에서 도는 순서를 **그림으로 따라가며 확인**. 온라인 강의의 손계산 예시(loss=9, dw=-18)를 자기 숫자로 한 번 더 재현한다

**[구현]** 동작하는 학습 루프 코드를 받아 그대로 실행해 손실이 낮아지는 것을 먼저 확인하고, **손실 계산 한 줄만 바꿔** 결과가 어떻게 달라지는지 관찰. 이후 모든 주차가 이 코드를 재사용하므로 **이 주차는 전원이 끝까지 돌려보는 것을 목표**로 함

**[실무]** AI Hub 「한국어 방언 발화(제주도)」의 **방언·표준어 대응쌍**으로, 방언 표기가 토크나이저에서 어떻게 쪼개지는지와 표준어 대비 토큰 수 증가를 실측. 같은 뜻을 담는 데 드는 비용이 표기에 따라 달라짐을 확인

□ 노트북 샘플 실측값 (KoELECTRA 토크나이저 기준)

| 방언 | 토큰 수 | 표준어 | 토큰 수 | 차이 |
|---|---|---|---|---|
| 혼저 옵서예. | 6 | 어서 오세요. | 4 | +2 |
| 마씀 | 2 | 말씀 | 1 | +1 |
| 고맙수다 | 3 | 고맙습니다 | 3 | 0 |
| 하르방 | 2 | 할아버지 | 1 | +1 |

- 방언 표기는 표준어 말뭉치로 학습된 토크나이저의 어휘에 덜 맞아 **더 잘게 쪼개지는 경향**이 있다. 토큰 수 증가는 곧 입력 길이·연산·비용의 증가다
- 같은 뜻인데 표기만 다르다고 비용이 달라진다면, 방언 화자를 대상으로 한 서비스의 단가 산정은 어떻게 해야 하는가. 이 질문이 실무 활동의 출발점이다
